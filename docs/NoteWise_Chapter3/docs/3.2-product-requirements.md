# 3.2 Product Requirements Document (PRD)

# NoteWise – Personalized Learning System from Lecture Materials

> **Artifact status:** `Draft for review`
>
> **Purpose:** Define a clear and testable product boundary for NoteWise.
>
> **Human action:** Product scope and requirements should be reviewed and approved before implementation.

## Product Goal
NoteWise enables students to transform their own lecture materials into structured and personalized learning activities. Students can upload learning documents, study important concepts, ask questions based on their materials, generate quizzes, review results, analyze learning performance, identify weak topics, and receive evidence-based recommendations for further study.

The product focuses on connecting learning materials with actual learning evidence. Instead of providing general AI responses without context, NoteWise uses the student's selected learning materials as the foundation for supported learning activities.

## Target Users
- University students.
- Independent learners.
- Students preparing for examinations.

## Product Scope
The current release includes student authentication, learning document management, document processing, AI-assisted summaries, document-based Q&A, quiz generation, quiz completion and evaluation, learning performance analysis, weak-topic identification, personalized recommendations, and learning history.

## Functional Requirements

### FR-01 — Student Authentication
A student can register and log in to access protected NoteWise learning features.

**Acceptance Criteria**
- A student can register using valid credentials.
- A registered student can log in successfully.
- Invalid credentials produce a clear and safe error message.
- Protected learning features require an authenticated session.
- A student can access only their own learning records.

### FR-02 — Manage Learning Documents
A student can upload, view, and delete supported learning documents.

**Acceptance Criteria**
- Supported documents can be uploaded.
- Unsupported or invalid files are rejected with a clear message.
- Each document has a visible processing state.
- A student can access only their own documents.
- Deletion requires intentional confirmation.

### FR-03 — Process Learning Documents
The system processes a valid uploaded document into usable learning content.

**Acceptance Criteria**
- Processing starts after a valid upload.
- The processing state is visible.
- Successful processing produces a `Ready` state.
- Failed processing produces a `Failed` state.
- A retry path is available when recovery is possible.

### FR-04 — Generate Document Summaries
A student can request a summary for a ready document.

**Acceptance Criteria**
- Only a ready document can be summarized.
- The summary is based on the selected document.
- Main ideas and important concepts are presented.
- Invalid or empty AI output is not presented as a successful summary.

### FR-05 — Document-based Q&A
A student can ask questions about a ready document.

**Acceptance Criteria**
- The question is associated with the selected document.
- Relevant document content is used before answer generation.
- The answer is grounded in available document content.
- If evidence is insufficient, the system clearly communicates the limitation.

### FR-06 — Generate Quizzes
A student can generate a quiz from a ready document.

**Acceptance Criteria**
- The student selects a document.
- Question count, question type, and difficulty can be configured.
- An optional topic can be selected.
- Generated questions are checked against source content.
- Invalid questions are rejected.
- A valid quiz can be persisted.

### FR-07 — Complete and Evaluate Quizzes
A student can complete a generated quiz and submit an attempt.

**Acceptance Criteria**
- Answers are captured.
- The score is calculated consistently.
- Correct and incorrect results are available.
- The attempt and result are persisted.
- Results can be used for later performance analysis.

### FR-08 — Analyze Learning Performance
The system analyzes learning performance at overall and topic levels.

**Acceptance Criteria**
- Overall performance is visible.
- Topic-level performance is available when sufficient data exists.
- Repeated attempts can be compared.
- Insufficient data is communicated instead of presenting false certainty.

### FR-09 — Identify Weak Topics
The system identifies topics that require additional attention.

**Acceptance Criteria**
- Topic-level evidence is considered.
- Recent or repeated performance may be considered.
- One incorrect answer alone does not automatically define a weak topic.
- The student can understand why a topic requires attention.

### FR-10 — Personalized Learning Recommendation
The system recommends next learning actions based on available student evidence.

**Acceptance Criteria**
- Quiz results and topic performance are considered.
- Learning history may influence recommendations.
- Relevant available materials are linked where possible.
- The reason for the recommendation is displayed.
- The system does not fabricate unavailable materials.
- The student remains in control of the next action.

### FR-11 — Learning History
A student can review previous learning activities and results.

**Acceptance Criteria**
- Quiz attempts and scores are persisted.
- Relevant topics are visible.
- History supports performance analysis.
- History can support later personalized recommendations.

## Non-functional Expectations
- **Security:** Students can access only their own learning records.
- **Reliability:** Processing and AI failures are visible and recoverable where possible.
- **Usability:** Primary learning actions and system states are understandable.
- **Performance:** Long-running processing exposes a visible state instead of appearing frozen.
- **Maintainability:** Document processing, AI assistance, analytics, and persistence remain separable.
- **Data persistence:** Learning records and progress survive reload when successfully saved.

## Assumptions
- Students provide learning materials they are authorized to use.
- Supported documents contain extractable textual content.
- AI-generated content is used as learning assistance and must be validated before being treated as successful output.
- Personalized recommendations depend on available quiz attempts and topic-level evidence.
- Topic-level analysis may be limited when there is insufficient learning history.
- The system does not guarantee academic improvement or examination performance.

## Non-goals
The current release does not include:
- Teacher or administrator management.
- Social or collaborative learning.
- General-purpose chatbot functionality unrelated to learning materials.
- Password reset.
- Email verification.
- SSO or social login.
- Guaranteed examination-score improvement.
- Fabricated learning materials.
- Uncontrolled AI recommendations.
- Unsupported integrations or features outside the approved product scope.

## Acceptance Signals
```text
Register / Login → Upload Material → Process Material
→ View Summary / Ask Questions → Generate Quiz
→ Complete Quiz → Persist Result → Analyze Performance
→ Identify Weak Topics → Receive an Explained Recommendation
→ Continue Learning
```

A successful product outcome can be observed through successful document processing, quiz completion, persisted results, performance analysis, and evidence-based learning recommendations.
