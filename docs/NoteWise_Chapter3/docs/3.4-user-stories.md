# 3.4 User Stories & Acceptance Criteria

# NoteWise – Personalized Learning System from Lecture Materials

## US-01 — Register and Log In
**User Story:** As a student, I want to register and log in to NoteWise so that my learning materials and learning history are protected and personalized.

**Acceptance Criteria**
- The student can register using valid credentials.
- The student can log in using registered credentials.
- Invalid credentials show a clear and safe error message.
- Protected learning features require authentication.
- The student can access only their own learning records.

## US-02 — Upload Learning Material
**User Story:** As a student, I want to upload my lecture material so that I can study from my own documents.

**Acceptance Criteria**
- Supported files can be selected and uploaded.
- Unsupported or invalid files are rejected with a clear message.
- The processing state is visible.
- The uploaded document belongs to the current student.
- The student can retry when processing recovery is available.

## US-03 — Manage Learning Documents
**User Story:** As a student, I want to view and manage my documents so that I can find useful learning material quickly.

**Acceptance Criteria**
- Owned documents are listed.
- Each document has identifiable information.
- Processing state is visible.
- The student can access a saved document.
- A document can be deleted after intentional confirmation.

## US-04 — View a Summary
**User Story:** As a student, I want to view a summary of my learning material so that I can understand important concepts faster.

**Acceptance Criteria**
- A ready document is required.
- The student selects the source document.
- Summary content is based on the selected document.
- Main ideas and important concepts are presented.
- Invalid or empty output is not presented as a valid summary.
- Generation failure provides a clear failure state and retry when possible.

## US-05 — Ask Questions About a Document
**User Story:** As a student, I want to ask questions about my document so that I can clarify difficult content.

**Acceptance Criteria**
- The student selects a ready document.
- The question is associated with the selected document.
- Relevant source content is used before answer generation.
- The answer is grounded in available source content.
- Insufficient evidence is communicated instead of fabricating an answer.

## US-06 — Generate a Quiz
**User Story:** As a student, I want to generate a quiz from my learning material so that I can practice what I learned.

**Acceptance Criteria**
- The student selects a ready document.
- Question count can be configured.
- Question type can be configured.
- Difficulty can be configured.
- An optional topic can be selected.
- Generated questions are related to source content.
- Invalid generated questions are rejected.
- A valid quiz can be stored.

## US-07 — Complete a Quiz
**User Story:** As a student, I want to complete a quiz and see my result so that I can evaluate my understanding.

**Acceptance Criteria**
- Answers are captured.
- The quiz can be submitted.
- The score is calculated consistently.
- Correct and incorrect results are available.
- The attempt and result are persisted.
- A persistence failure is not incorrectly reported as a successful save.

## US-08 — Understand Learning Performance
**User Story:** As a student, I want to see my performance by topic so that I know where I need more practice.

**Acceptance Criteria**
- Overall performance is available from persisted results.
- Topic-level performance is displayed when sufficient data exists.
- Repeated attempts can be compared when available.
- Insufficient data is communicated.
- One incorrect answer does not automatically define a weak topic.

## US-09 — Receive a Personalized Recommendation
**User Story:** As a student, I want a recommendation based on my learning results so that I know what to study next.

**Acceptance Criteria**
- Recommendations use student-specific evidence.
- Quiz results and topic performance are considered.
- Learning history may influence priority.
- The reason for the recommendation is displayed.
- Relevant available material is linked where possible.
- Unavailable material is not fabricated.
- The student can choose whether to follow the recommendation.

## US-10 — Review Learning History
**User Story:** As a student, I want to review my learning history so that I can track my learning over time.

**Acceptance Criteria**
- Previous quiz attempts are visible.
- Scores are visible.
- Relevant topics are visible.
- Learning history persists after successful saving.
- History can support later performance analysis and personalization.

## Traceability
These user stories describe observable student behavior and can be used as a basis for product design, implementation, and testing.

```text
Authentication → Learning Material → Study → Practice
→ Results → Performance Analysis → Recommendation
→ Continued Learning
```
