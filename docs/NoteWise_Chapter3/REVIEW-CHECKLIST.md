# Chapter 3 — Review Checklist

## PRD review

- [ ] Product problem and opportunity are clear.
- [ ] Target users are clear.
- [ ] Goal is observable.
- [ ] Core learning journey is explicit.
- [ ] Functional requirements have acceptance criteria.
- [ ] Requirements analysis covers priorities, dependencies, constraints and risks.
- [ ] User stories trace to requirements.
- [ ] Non-goals prevent scope expansion.
- [ ] Authentication/authorization are explicit.
- [ ] Persistence is explicit.
- [ ] AI boundaries are explicit.
- [ ] Success signals are observable.
- [ ] No unsupported feature is presented as committed scope.

## Feature specification review

- [ ] Every primary action has a success path.
- [ ] Every primary action has a failure path.
- [ ] Recovery behavior is defined where possible.
- [ ] Validation behavior is explicit.
- [ ] Persistence survives reload.
- [ ] Authorization/resource ownership is explicit.
- [ ] Invalid AI output is rejected.
- [ ] Insufficient information is handled.
- [ ] Recommendation reasons are visible.
- [ ] Recommendations use available materials only.
- [ ] Destructive actions require confirmation.
- [ ] Loading and empty states are covered.
- [ ] Terminology is consistent.

## Approval rule

The canonical PRD and Feature Specification become `Accepted` only after human review is complete and confirmed scope-changing findings are resolved.
