# 3.3 Requirements Analysis

# NoteWise – Personalized Learning System from Lecture Materials

## Purpose
Requirements analysis transforms product needs into clear, testable, and implementable requirements.

The core NoteWise learning journey is:

```text
Upload Material → Process Material → Study → Practice
→ Review Results → Analyze Performance → Receive Recommendation
```

## Requirement Categories

### 1. Authentication and Access Requirements
Students need an authenticated session to access protected learning features. Learning materials, quiz attempts, results, and learning history must be associated with the correct student. The system must prevent unauthorized access to another student's protected data.

### 2. Learning Document Requirements
Students need to upload, store, view, and manage lecture materials. The system must accept supported formats, reject invalid files, show processing states, preserve ownership, and provide clear failure behavior.

### 3. AI-assisted Learning Requirements
The selected learning material is the source for AI-assisted learning activities:
- Document summarization.
- Document-based question answering.
- Quiz generation.

AI output must be checked before being presented as successful learning content. When source information is insufficient, the system must communicate the limitation rather than inventing information.

### 4. Practice and Evaluation Requirements
Students need quizzes generated from learning materials. The system captures answers, evaluates attempts, calculates results, and stores relevant learning evidence.

### 5. Learning Performance Requirements
The system analyzes persisted quiz results to provide overall and topic-level learning performance. Topic-level conclusions depend on sufficient evidence.

### 6. Personalized Learning Requirements
The system uses available student-specific evidence to identify topics requiring attention and suggest possible next learning actions. Recommendations must provide an understandable reason and must not fabricate unavailable materials.

## Prioritization

### Must Have
- Student authentication and protected access.
- Document upload and processing.
- Document management.
- Document summaries.
- Document-based Q&A.
- Quiz generation.
- Quiz completion and evaluation.
- Result persistence.
- Topic-level performance analysis.
- Weak-topic identification.
- Personalized recommendations.

### Should Have
- Rich learning history.
- Repeated-attempt comparison.
- Source references for supported Q&A responses.
- Optional topic selection for quiz generation.

## Dependencies
- Authentication and session management.
- Document content extraction.
- Persistent storage.
- AI assistance for summaries, Q&A, and quiz generation.
- Quiz evaluation logic.
- Topic performance calculation.
- Recommendation logic.

## Constraints
- Documents may contain insufficient extractable information.
- AI output may be incomplete, invalid, or unrelated to source content.
- Recommendations depend on available student evidence and materials.
- Topic-level analysis may be unreliable when too little data exists.
- Processing time may vary depending on document size and system load.
- Students can access only their own protected learning data.

## Risks

| Risk | Impact | Response |
|---|---|---|
| Invalid AI output | Incorrect learning content | Validate output before display or persistence |
| Insufficient document evidence | Unsupported answer or summary | Show an insufficient-information state |
| Weak-topic misclassification | Poor recommendation | Use topic-level and repeated evidence |
| No relevant material | Weak next action | Recommend only available materials |
| Unauthorized access | Privacy issue | Enforce authentication and ownership |
| Processing failure | Learning interruption | Show failure state and retry when possible |
| Lost result data | Incorrect learning history | Confirm persistence before reporting success |

## Requirement Boundaries
The application controls authentication, authorization, document ownership, processing states, source selection, AI-output validation, quiz configuration, quiz evaluation, result persistence, performance calculation, weak-topic identification, recommendation behavior, and error recovery.

AI assistance does not control product authorization, persistence, ownership, or final business rules.

## Conclusion
Requirements analysis keeps NoteWise focused on personalized learning from the student's own lecture materials. The requirements remain observable and testable so product, design, development, and testing decisions use the same product boundary.
